# Change Log

## 0.4.24 — 2026-10-25 (更新强停直连，Windows Test)

- **更新停止直连化**：更新不再请求 Manager 优雅停止（杜绝 active_requests 弹窗与竞态），直接按运行记录终止当前 Core（指纹校验、等待退出确认、通知托盘），随后立即移交安装器。
- **侧边栏进度条改细线**：下载进度以行底部 2px 强调色细线呈现，行身保持平静。

## 0.4.23 — 2026-10-25 (进度条配色修复，Windows Test)

- **侧边栏更新进度改用主题强调色**：下载填充、安装流动线与收起态圆点此前使用中性选中色，暗色主题下与表面几乎不可分（观感为灰色）；现改为主题自适应的 accent 蓝，与全站进度语义一致。

## 0.4.22 — 2026-10-25 (账号验证空窗修复，Windows Test)

- **网络波动不再踢出工作区**：云端验证快照过期时，曾验证过的凭据在 10 分钟宽限内保留 Web 工作区准入（仅覆盖被动过期；主动发起的验证失败、凭据过期/注销仍立即关闭）。欢迎页区分「暂时无法确认（自动重试）」与「尚未验证（需点击验证）」两种状态。
- 携带 0.4.21 的会话内更新发现（每 15 分钟检查）。

## 0.4.21 — 2026-10-25 (会话内更新发现，Windows Test)

- **打开期间持续发现新版本**：Desktop 运行中每 15 分钟强制读取一次签名版本信息（仅元数据），会话中途发布的版本几分钟内自动出现在侧边栏，无需手动刷新或重启。

## 0.4.20 — 2026-10-25 (更新不再被 Core 状态阻挡，Windows Test)

- **强停兜底**：更新安装阶段若 Manager 保护的停止被拒（有活跃客户端或任务），按运行记录精确终止当前 Core 进程（指纹校验，绝不误杀）并通知托盘退出，更新始终完成——点击更新即操作者授权。
- 安装器启动前等待全部实例退出（互斥量有界等待），启动即检查版本，侧边栏更新条新样式。

## 0.4.19 — 2026-10-25 (更新可靠性修复，Windows Test)

- **安装不再被退出竞态打断**：更新助手在启动安装器前等待托盘等残留实例完全退出（最长 60 秒，超时明确报告），修复 0.4.18 更新报「未完成，可能仍有窗口或客户端正在运行」的失败。
- **启动即检查更新**：打开 Desktop 立即检查一次版本（仅读元数据），新版本不再受 24 小时周期限制，侧边栏与设置页第一时间出现更新入口。
- **侧边栏更新条重做**：就绪态带下载图标与浅色强调，下载进度以整行底色填充并显示百分比，安装态为流动进度线，收起侧栏时为圆点小方块。

## 0.4.18 — 2026-10-25 (UI 精致度收敛，Windows Test)

- **字号阶梯**：全站 19 种字号收敛为 12/13/15/18 四档，最小 12px；信息层级由字重与灰阶承担，不再靠缩小字号。
- **分隔符与细节**：全站移除中点"·"分隔符（改间距/1px 细线/弱化色），移除 toast 与提示块的彩色左条，圆角收敛为 4/6/8/12 四档。
- **文案减负**：原生维护对话框压到两行（保留拒绝与不强制中断承诺），更新卡片与设置提示去掉复述机器行为的说明。
- **VS Code 会话侧栏**同套规范（字号/分隔符），删除已被共享设置面板取代的旧配置面板（约 3300 行死代码）。

## 0.4.17 — 2026-10-25 (应用内更新，Windows Test)

- **应用内更新流程**：更新入口移入设置页卡片与侧边栏底部（账号区上方）——静默自动检查发现新版本后侧边栏出现一行式入口，点击即下载并安装；卡片内展示真实进度（百分比/取消），下载验证通过后自动停止共享 Core 并运行安装器，全程无需确认弹窗（有 AI 任务或活跃客户端时仍被 Manager 明确拒绝，不强制中断）。
- **托盘精简**：移除"检查更新/取消下载/自动检查"菜单项与维护菜单，仅保留打开与退出；每日版本检查静默运行。
- **更新文案纠偏**：版本信息与安装包来源统一为 GitHub Releases 签名清单（移除错误的"由 Cloud 提供"表述）。

## 0.4.16 — 2026-10-25 (跨平台打包链修复，Windows Test)

- **打包脚本平台化**：Core 归档组装、VSIX 打包与审计的平台参数贯通（`--platform/--arch`），非 Windows 归档不再包含 Windows 专属的 handoff 成员。
- **CI 环境自洽**：打包脚本在无本机 test.json 的环境（CI runner）以显式 cloud 参数完成配置解析，host bundle 重建同样透传。
- **跨平台 CI 全绿**：linux-x64/arm64、macOS-x64/arm64 四平台 Core+VSIX 打包矩阵通过。

## 0.4.15 — 2026-10-24 (Desktop 更新通道接线，Windows Test)

- **更新通道**：Desktop 构建内置 GitHub Releases 更新源与 ed25519 公钥 pin，托盘"检查更新…"可下载并安装经签名校验的新版本；测试通道滚动 tag `desktop-test`。
- **信任根报错可辨识**：宿主信任根缺少 Core 签名钥匙时改报 `core_trust_root_missing`（附钥匙 ID），提示升级插件/Desktop，不再误报为归档损坏。

## 0.4.14 — 2026-10-24 (Desktop 自动退出修复，Windows Test)

- **心跳容错**：Desktop 租约续期遇到 Manager 锁竞争、daemon 探测超时等瞬时错误时，只要租约仍在有效期内就保留租约并等待下一拍重试，不再单次失败即退出应用；明确的租约失效拒绝（过期、身份冲突等）仍然立即解绑退出。
- **心跳忙碌重试**：Manager CLI 的 heartbeat 命令与其他命令一致获得 2.5 秒的锁忙碌重试预算。
- **Desktop 运行日志**：启动器把附加、心跳延迟、租约丢失与托盘退出原因写入 `~/.blackhole/logs/desktop.log`，自动退出可留痕排查。

## 0.4.13 — 2026-10-24 (设置维护入口打磨，Windows Test)

- **设置-高级停止确认文案修正**：VS Code 停止共享 Core 的确认框不再残留重启文案，改为与 Desktop 一致的"停止后数据和 Core 文件保留，可再次启动"。
- **Desktop 维护错误提示可读**：原生错误框中的维护请求无效、配置版本无效、事务读取/接纳/恢复失败等场景补齐中文说明，错误码保留为前缀便于排查。
- **高级页危险区样式统一**：停止后台服务与重启后台服务使用同一行结构（标题/提示在左、按钮在右），Web、VS Code、Desktop 三端同步生效。

## 0.4.12 — 2026-10-23 (首次安装与并发启动，Windows Test)

- **首次启动等待共享 Core**：端点及运行状态查询在 Manager 锁被其他启动占用时最多等待 45 秒，短暂竞争不再立即报告 `lock_busy` 或更新状态不可用。
- **重装验证**：验收使用实际 VSIX 安装到空白 VS Code 用户目录，覆盖首次安装、再次安装及超过 15 秒的锁占用，检查后台身份、客户端租约和启动错误日志。
- **保留安全边界**：只读查询继续经过互斥锁；损坏锁、长期占用及不确定更新结果仍明确拒绝，不删除用户数据、不另启后台、不重放写操作。
